# OrgForms reliability review — 29 October 2026

The initial working tree was clean. No AGENTS.md was present in the repository or checked parent directories. Universal Platform Architecture v3 remains the product plan; Local and Cloud Architecture remains deployment guidance. This was a bounded review and repair pass, not acceptance of the entire target architecture.

## Changes

- Dataset detail now filters connected collections through the existing form visibility policy. A dataset read grant no longer discloses restricted collection titles. Explicit form access still reveals the connection.
- Library provides an Add record action for write-only members without exposing records or their counts. The action sits below the dataset name, remains visible at phone widths, has a dataset-specific accessible name and a 44px minimum height. Archived datasets/organizations do not offer creation actions. Write-only saves and cancellation return to Library.
- Library AI drafting honors the organization default model, explicit model overrides and the requested thinking setting. It remains local-only and review-before-save.
- Local drafting validates Ollama response envelopes before consuming message content. Malformed messages produce an actionable 422 response rather than an uncaught exception.
- Library is a reserved form slug in automatic generation and API validation. A form titled Library receives library-form. The current database had zero existing forms with the conflicting slug; no URLs or records were migrated.
- AI creation tests clear their throttle cache between cases. Added requests exposed shared cache state causing unrelated chat tests to return 429; production throttling is unchanged.

## Remaining work, in priority order

1. **Separate collection action grants.** Current visible_forms / require_form_records policy lets ordinary members read responses for visible public/organization forms; explicit restricted-form grants also grant response access. This is the documented baseline, but v3 calls for distinct submit, edit, results and process permissions. Define backward-compatible defaults and test revocation across views, CSV, attachments, history and AI retrieval before broader rollout.
2. **Make large datasets and histories navigable.** Dataset HTML lists stop at 100 rows, histories at 200, and CSV at 5,000. Record-reference forms load at most 200 choices. Add bounded pagination/search and explicit export completeness rather than silently inaccessible older entries. Some Data/Library terminology remains inconsistent outside this repair.
3. **Finish the reference workflows.** Survey capture/quota foundations exist; department approval, work queues, voice/API equivalence and resource limits are incomplete. Catalog items and dataset records are still separate sources; dataset-backed item cards and nested selection questions remain proposals.
4. **AI task policy and resilience.** Durable bounded inference queue, task-level cloud consent/budgets and tenant-specific hosted credentials remain open. Review the older api_form_draft fallback, which can report a deterministic starter as success after inference failure, alongside the newer explicit local-creation endpoint. Live model failure and resource-contention drills remain necessary.
5. **Production data-home acceptance.** Consistent database/media backup with tested restore, HTTPS/service lifecycle, installer, retention and outage drills remain unverified. Device wallet, optional cloud distribution/backups/projections and hosted-workspace isolation remain later architecture stages.
6. **Broader UI acceptance.** Complete keyboard/focus, contrast, long-content and mobile checks across the builder, People, history, settings and AI Hub. This pass visually checked the affected Library workflow, not every screen.
